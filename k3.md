## Bugs & correctness (new)

### k3-B1 · Local branches with slashes render as remote-branch chips — S — VERIFIED
`GitParsers.parseDecorations` classifies any decoration containing "/" as
`.remoteBranch`. `%D` emits short ref names, so a local branch `feature/foo`
(the single most common naming convention) gets the gray network-icon chip
instead of the accent local-branch chip, everywhere in History.
Reproduced: `git branch feature/foo` → `%D` → `feature/foo` → misclassified.
**Fix:** switch `GitClient.log` to `--decorate=full` (emits `refs/heads/…`,
`refs/remotes/…`, `tag: refs/tags/…` — exact classification by prefix) and
rewrite `parseDecorations` around those prefixes, keeping the old heuristics
only as a fallback. Update `GitParsersTests` to full-form input.

### k3-B2 · Spurious `origin/HEAD` chip on the default-branch tip — S — VERIFIED
`%D` includes the remote HEAD symref: every repo with a remote shows a noise
`origin/HEAD` chip on the tip commit of the remote's default branch (reproduced
live). The `branches()` parser already filters this symref; decorations don't.
**Fix:** same `--decorate=full` change — drop `refs/remotes/*/HEAD` in
`parseDecorations`. Lands with k3-B1 as one PR.

### k3-B3 · Selecting an untracked *directory* shows a silently-empty diff — S — VERIFIED
`status --untracked-files=normal` collapses fully-untracked directories to a
single `dirname/` entry. Selecting it runs
`git diff --no-index -- /dev/null dirname/`, which **errors**
(`Could not access 'dirname/null'` — git joins the basename against the
directory; reproduced on git 2.39). `selectFile` swallows it (`try? … ?? ""`)
and the pane shows "No diff" for a folder full of new files.
**Fix:** in `GitClient.diffForUntracked`, when the path ends in "/", run
`git ls-files --others --exclude-standard -z -- <path>` and return a synthetic
listing ("N untracked files in dirname/…") instead of a patch. Integration
test: untracked dir with files → listing contains the file names; plain
untracked file still returns a patch.

### k3-B4 · Discard of a staged rename leaves a half-done state — S/M
`git mv old new` then "Discard Changes" on `new`: `discard(paths:)` resets only
the pathspec `new` (the staged deletion of `old` survives), `ls-files -- new`
comes back empty so nothing is checked out, and the result is `D old` staged +
`new` untracked — precisely the rename the user asked to throw away, restaged
as two pieces. (`FileChange.originalPath` is right there, unused, on the
discarded change.)
**Fix:** when discarding a change with `originalPath`, reset both paths,
`checkout --` the original, and move the renamed file to the Trash like any
other untracked file. Integration test mirroring the existing discard suite.

### k3-B5 · "Conflicted Files (0)" section renders during conflict-free operations — S
`ChangesView.fileList` shows the conflict section whenever
`conflictUIActive` — i.e. for the entire duration of a merge/rebase/
cherry-pick, including after the last conflict is resolved, when it renders a
header reading "Conflicted Files (0)" above zero rows.
**Fix:** gate on `conflictUIActive && !conflicts.isEmpty`.

### k3-B6 · Amend offered on an unborn HEAD — S
On a repo with no commits yet, the Amend toggle stays enabled; committing then
dies with git's raw `You have nothing to amend`. **Fix:** disable the toggle
while `status.isUnborn` (and force it off).

### k3-B7 · Pull/Push available mid-merge/rebase — S
During any in-progress sequencer operation, Pull dies with git's raw
`You have not concluded your merge` and Push (detached mid-rebase) with
`You are not currently on a branch`. **Fix:** disable Pull and Push in the
toolbar while `mergeState.isInProgress` (Fetch stays — it is always safe).

### k3-B8 · SIGPIPE can kill the app on a large stdin write — S
`GitShell.runWithStdin` writes the commit message on a helper thread. If the
child exits before draining stdin (a fast-failing `git commit -F -`, e.g.
index.lock contention) and the message exceeds the pipe buffer, `write()` on
the broken pipe raises SIGPIPE — default disposition terminates the process.
Window is small (git reads `-F -` early) but the crash is total and the
one-line mitigation is standard for anything that pipes to children.
**Fix:** `signal(SIGPIPE, SIG_IGN)` at launch (`AppDelegate`), which turns the
write into a thrown error instead of a kill. Not verified on macOS (no
toolchain here) — mitigation is harmless regardless.

### k3-B9 · Long commit bodies are truncated with no way to read them — S
`CommitDetailView` caps the body at `lineLimit(6)`; longer messages (the
project's own merge commits!) are unreadable in-app.
**Fix:** a "Show more / Show less" toggle when the body exceeds six lines.

## Performance (new)

### k3-P1 · Every app operation triggers a second, full refresh ~2.5 s later — S
`RepoViewModel.perform` already ends with a full snapshot (status + branches +
stash + **complete `git log` + graph layout**). But the operation itself dirties
`.git/index`, `HEAD`, `logs/HEAD`, … — so the `RepoWatcher` signature trips on
its next tick and `collectAndApply(includeHistory: true)` runs the *same* full
snapshot again. Every commit/stage/checkout pays double, and the redundant pass
is the expensive one (topo-sort + lane layout on every loaded row).
**Fix:** `RepoWatcher.restamp()` — recompute the baseline signature on the
repo queue right after `perform`'s snapshot (same queue as the timer, so it
serializes with ticks). Documented race: an external change landing between
snapshot and restamp is absorbed into the baseline — bounded to one poll
interval, with app-activation refresh as backstop.

### k3-P2 · App activation reloads the entire history, every time — S
`applicationDidBecomeActive` → `refresh(includeHistory: true)`: every Cmd-Tab
back to GitEnough re-walks the full topo log and re-lays the graph on the
active repo (plus a sidebar-summary pass on *all* repos). The 2.5 s watcher
already catches genuine ref changes — including ones made while the app was
backgrounded (its timer fires promptly on activation, even after App Nap).
**Fix:** activation refresh with `includeHistory: false` (status/branches/
stash — cheap), letting the watcher own history invalidation. History visibly
lags external changes by ≤ one poll interval in the worst case.

### k3-P3 · (supporting evidence for ANALYSIS G9) — queued ops clobber each other
Two `perform`s in flight: the second immediately nils `errorMessage` and
overwrites `activity` on the main thread, and the first finisher flips
`isBusy = false` while the second still runs. Not new — folded into G9's
operation-counter fix — but the error-banner-eats-error failure mode is worth
adding to G9's list.

## Interaction & UX (new)

### k3-U1 · History filter ignores ref names — S
The filter searches subject/author/hash only. The chips are right there on the
rows, yet typing a tag (`v1.0`) or branch name matches nothing.
**Fix:** extend the predicate to decorations (names, case-insensitive);
update the placeholder to "subject, author, hash, or ref".

### k3-U2 · Branch names are only validated after the fact — S/M
New-branch sheets (toolbar + history context menu) and the rename sheet accept
anything; invalid or duplicate names surface as a raw git error banner.
**Fix:** `git check-ref-format --branch <name>` (one cheap call, debounced, or
validated on submit before dispatch) → inline error + disabled Create button.
Also reject leading "-" in the UI like the tag sheet already does.

### k3-U3 · No multi-select in Changes — M
Stage/unstage/discard are strictly one-file-at-a-time (per-row button) or
all-files ("Stage All"). GitHub Desktop parity needs ⌘/⇧-click multi-select
with bulk actions on the selection. Medium because the rows currently manage
their own single-selection state by hand.

### k3-U4 · No "Open in Editor" for the repository — S
The Repository menu has Show in Finder / Open in Terminal; the everyday third
option ("Open in VS Code" — `open -a` against detected editors) is missing.
Small; detection mirrors `MergeTool`'s pattern.

## Visual & layout (new)

### k3-V1 · Push/Pull buttons give no count feedback — S
GitHub Desktop shows the payload right on the button ("Push 2"); GitEnough's
toolbar buttons are static and the ahead/behind counts hide in the status bar
at the bottom. **Fix:** render "Push (2)" when `ahead > 0`, "Pull (1)" when
`behind > 0` — data already on `status`.

### k3-V2 · Commit detail hides its parents — S
`CommitDetail.parents` is parsed and never shown; you can't walk history from
the detail pane, and merges don't say they are merges.
**Fix:** a "Parents: abc1234, def4567" row of clickable short-hash chips that
select the parent commit (plumb an `onSelectCommit` closure from HistoryView),
plus a "Merge" label when `parents.count > 1`.

### k3-V3 · DiffView has no soft-wrap toggle — S
Minified/generated one-line files (package-lock.json, .pbxproj) force an
endless horizontal scroll. **Fix:** a wrap toggle (persisted) that drops the
horizontal scroll axis and lets lines wrap. Pairs with V3's whitespace toggle
in ANALYSIS but is independent and much smaller.

## Missing features (new; big-ticket items live in ANALYSIS)

### k3-M1 · Delete remote branch — S
Local branches can be deleted; remote ones can't (`push <remote> --delete`),
so stale branches accumulate until the user drops to a terminal. Context menu
on remote branch rows + confirmation. Complements ANALYSIS M4/M20.

### k3-M2 · `git maintenance` affordance for large repos — S
For the "opened a monorepo" case: one Repository-menu item running
`git maintenance run` (commit-graph, incremental gc — safe, online). Cheap,
genuinely useful, and on-brand for a client that stays close to the CLI.

## Novel / delightful (new)

### k3-Q1 · Clickable decoration chips — S/M
The ref chips on history rows are inert text. Give them a context menu (and
⌘-click): local branch → Check Out / Rename; tag → Copy Name / Delete; remote
branch → Open on Forge (reuses `ForgeRepo`). Turns decorative metadata into
navigation — the cheapest big "feel" win in this document.

### k3-Q2 · "Copy as cherry-pick command" — S
History context menu: `git cherry-pick <short-hash>` onto the clipboard for
terminal-hybrid users. One line; surprisingly sticky habit.

### k3-Q3 · AI-suggested branch names — S
The New Branch sheet gets a ✨ button: staged diff (or current branch's
unpushed subjects) → configured LLM → a suggested name, editable before
creating. Reuses `CommitMessageGenerator` plumbing with a different prompt;
very on-brand.

### k3-Q4 · Merge commits say what's merging — S
The history row of a merge shows only the subject ("Merge branch 'x'").
Parsing the second parent into a subtle "← feature" suffix on the row (the
data is in `parents` + decorations) makes the graph legend-free.
